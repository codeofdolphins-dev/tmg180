Platform Governance

The admin sees that the system is working — never what anyone wrote in it. Counts, standing, verification stamps and access trails. No daily-note text, no snapshot narratives, no profile answers. Routine administration must never mean browsing participant content.

Non-negotiables · governance

Metadata only, always. Counts, statuses, dates, provenance and access events. Never record content.

Least privilege. Routine administration must not mean unrestricted browsing of participant content — a canon rule, not a preference.

Provisioned, never self-served. Admin is outside the sign-up path; the seed script is the only way an account comes to exist.

Verification attests to a document. An empty credential row can't be verified — and a later edit clears the stamp.

No service-delivery oversight. Governance verifies eligibility and handles standards. It never supervises how a worker works.

Standing is never a rating. No scoring, ranking or league table of workers — counts of what is in order.

Every sensitive act is auditable. Share, revoke, access, finalise — with actor, object and time.

Real numbers or none. What the platform can't measure is shown switched off, never filled with a plausible figure.

The Longitudinal package says relatively little about admin directly — but what it says is sharp, and it creates real work.

Open flags · governance

  1. "Governance Admin" is a banned term — still live as a card title on the Admin Profile screen. Small fix, real rule.
  2. Who reviews derived AI text? The canon requires a reviewer identity and status but never says whose job it is — participant, worker, or governance.
  3. Incident tickets have no data model — four admin screens are drawn against a concept that has never been specified.
  4. Reports generate nothing — the detail and creation screens exist; there is no report record, no export, no schedule.
  5. Admin verification is the only write — confirm no other governance action is expected to change a record, or the least-privilege posture needs revisiting deliberately.
  6. Suspension has a backend but no screen — revoking all sessions is built and wired to password reset; an admin suspension flow should call it too.
