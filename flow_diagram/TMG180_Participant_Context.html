My Personal Profile — the 25 Aug Canon

The Personal Profile is both a participant-facing living document and the baseline of the longitudinal evidence chain. Fourteen modules, verbatim canonical copy, versioned answers that never overwrite history — the system holds the memory while the participant retains the voice.

Non-negotiables · participant-facing digest

A living document, never backend intake. The participant reads back exactly what they entered — always.

Verbatim canonical copy. Exact prompts, exact options, canonical order. Length is a UX problem, not a content one.

Edits supersede, never overwrite. Every answer snapshots its prompt wording; history stays queryable.

"Not sure" is an answer. Prefer-not-to-answer and not-applicable are stored values, never null.

One document, fourteen modules. Continue / Review My Personal Profile — never fourteen separate assessments.

Save and return anywhere. No forced completion of optional questions, no data loss part-way.

Sharing is granted, scoped, revocable. Full profile or selected modules; workers see nothing by default.

Nothing edits the Profile but the participant. Monthly "may need updating" raises a review prompt — it never writes.

Build slices — one by one

Participant type first. Each slice lands with its release-blocker acceptance tests from spec §19; the built 11-section profile stays untouched until P3.

P0

Definition layer + seed import

New tables mirroring the reference SQL's intent: versioned, immutable-once-active definitions holding verbatim content + SHA-256, and a response table with prompt snapshots and a supersede chain. An idempotent importer reads the canonical JSON — and derives the interaction model (free-text / multi-select / headings / repeatable goals) deterministically, never editing text.

"My Personal Profile" renderer

The 14-module hub plus one generic module page rendering the active definition and current responses: explanatory copy, topic headings, free-text, multi-selects with "Other" inlines, repeatable goals, per-module progress, save-and-return. Participant UI scale — no Figma frames exist for these modules yet.

Migration — §18, no rip-out

Field-by-field review found no defensible exact matches between the 74-key 11-section contract and the 14 modules — so every current answer is preserved as read-only legacy (visible, flagged, never guessed into a new field) and participants enter the new modules fresh. The one live wire: the goals evidence chain (1–3 goals per daily log) keeps working throughout.
