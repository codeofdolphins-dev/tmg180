## What TMG180 is (one paragraph)

TMG180 ("The Middle Ground 180") is a relationally governed NDIS digital support ecosystem — governance infrastructure, **not** a provider, employer, marketplace, or clinical system. Three portals: Participant, Worker, Admin (Platform Governance). Core model: participant-owned longitudinal evidence chain — **Personal Profile (FCA intake, internal `FCA_BASELINE`) → Daily Support Evidence Logs → Monthly Snapshots** — append-only after approval, exportable for NDIS plan reviews. No matching, no booking, no rostering: participants browse verified workers and contact them directly. Relational (non-clinical, dignity-preserving) language is enforced at system level via a terminology registry and banned-terms table. Stack: React + Vite + Node + Express + Postgres.

## Cross-cutting non-negotiables

- **Build authority order:** Final Override bundle (July 2026) → canonical technical pack (docs 14–20) → everything else. If it's not in the bundle/canon, don't invent it. Withdrawn worker-matching screens must never be revived.
- **Language:** all UI text from the terminology registry (no hardcoded strings). Banned: match/matching, tasks, assigned caseload, productivity, programs, clinical notes, ACTION REQUIRED, non-compliant, Care Management, Governance Admin, FCA Baseline/Assessment in participant UI.
- **Evidence rules:** daily note cannot finalise without 1–3 goals (from intake) + functional domain tags; monthly snapshot always includes the non-linear fluctuation statement; participant approves snapshots before locking; locked records are addendum-only (never edited).
- **Boundaries:** no matching/ranking/assigning workers; no booking/rostering; AI is draft-only behind a human review gate; participant voice never completed by workers; worker private narrative (WCPS Layer A) never shared.
